# 知序 · 复习题库

一个可以发布到 GitHub Pages 的中文题库。学生无需登录即可查看；教师使用 Supabase 账号管理题目和个人学情。

**当前状态：代码已提供。数据库尚未连接；未配置数据库时页面仅供演示。**

## 本地体验

安装 Node.js 后，在本目录运行 `npm start`，访问 http://127.0.0.1:4173 。无需安装依赖。

未设置数据库时自动进入演示模式，内含明确标注的数学示例。点击左下角“教师入口”可体验添加题目、编辑难度、上传多图、记录个人学情及导出 CSV。数据仅保存在该浏览器；清理浏览器数据会丢失。不要在演示模式录入正式学生数据。演示不会自动导入云端。

## 首次正式部署（一次配置，之后直接网页维护）

1. 将本目录内的 docs、supabase、scripts、tests 文件夹以及 README.md、package.json 等文件上传到 GitHub 仓库根目录（不要把外层 study-bank-github 文件夹再套一层）。
2. 在 [Supabase](https://supabase.com/dashboard) 创建数据库项目，在 SQL Editor 中粘贴并运行 `supabase/schema.sql`。SQL 适用于新项目，完整执行一次；已运行成功后不要重复运行。
3. 在 Authentication → Users 中创建教师账号，使用邮箱和密码并完成邮箱确认。在 SQL Editor 中执行 `insert into public.teachers(user_id) values ('替换为刚创建账号的UUID');`。关闭公开注册或按需管理；普通注册用户即使登录也没有教师权限。教师忘记密码时，在 Supabase 控制台恢复账号。
4. 打开项目的 Connect / API 设置，找到 Project URL 和 publishable key（或 legacy anon key）。修改 `docs/config.js` 的 `url` 和 `key`，保持字符串引号。**只用公开 key，绝不把 secret key、service_role key、数据库密码或教师密码放入代码。** 公开 key 的数据权限由 SQL 中的 RLS 控制。
5. 在 GitHub 仓库 Settings → Pages → Build and deployment，将 Source 设为 **Deploy from a branch**，Branch 选择 **main**，目录选择 **/docs**，点击 Save。等待 GitHub 自动构建。
6. GitHub Pages 设置页会给出正式访问链接。先以无痕窗口验证学生访问，再用教师账号验证保存题目、图片、个人记录；在另一浏览器查看同步。测试完成前不要发给学生。

GitHub 只发布 `docs/` 目录。题目、图片和学情保存在 Supabase，网页修改数据无需重新提交 GitHub。跨设备自动刷新间隔 10 秒；浏览器后台暂停，返回立即刷新。不是毫秒级推送。断网时显示同步失败，不能离线提交。

## 日常使用

- 一节复习结束后：登录教师 → 添加题目 → 输入章节与小节 → 输入文字、上传多张图片或仅传图片 → 设置 1–5 级难度 → 保存并公开。答案与解析也是公开内容。
- 全班汇总：在“编辑题目”内填写历史补录完成/错误次数；错误率自动计算为错误次数 ÷ 完成次数。
- 逐人学情：在题目卡片点击“记录学情”，使用稳定的学生编号或化名，输入该学生该题的**累计**完成及错误次数。同编号同题只保存一条记录。个人记录自动计入公开汇总，勿重复补录。
- 已有历史补录后改用逐人登记：先减少对应历史补录，再录入个人记录，以免重复。
- 在“学生学情”查看与修改逐人记录，支持导出 CSV。此功能仅授权教师可以访问。首版不提供学生账号、自行提交答案、自动判题、试卷 PDF/OCR、批量导入或教师各自隔离的数据空间。
- 多位教师共享同一题库与全部学情。修改已有题目/个人记录时有版本冲突检测，发生冲突后刷新再编辑。

## 数据与权限

| 数据 | 学生（未登录） | 普通已登录用户 | 授权教师 |
| --- | --- | --- | --- |
| 题目、答案、图片、难度、全班汇总 | 查看 | 查看 | 维护 |
| 逐人完成与错误记录 | 不可访问 | 不可访问 | 查看与维护 |
| 教师授权名单 | 不可访问 | 不可访问 | 仅控制台管理员管理 |

`question_public` 是有意公开的聚合视图，只输出题目与汇总，不输出个人标识。小班级仍可能从汇总推测单人表现，请根据实际班级规模决定公开内容。姓名不要填写在题干、图片、解析或公开字段中。图片桶为公开题图专用，禁止上传学生个人资料。已上传图片即公开，浏览器/CDN 可能留有缓存。

教师会话只保存在当前页面内存，刷新页面需重新登录；数据库 RLS 是真正的权限边界，隐藏按钮不能代替数据库权限。所有正式写操作要求授权教师 JWT。教师身份只能由数据库管理员添加。

删除题目会级联删除关联学情。移除图片和删除题目不会自动清理 Storage 中的图片文件，上传中断也可能留下未引用文件；请由管理员在 Storage 中定期清理确认不再使用的图片。定期在 Supabase 控制台备份数据库和 Storage 图片。CSV 仅为个人学情导出，不是完整数据库备份。服务额度、区域网络连通性和可用性需在实际账号中验证。

## 上线验收

1. 学生无痕访问：看到公开题目，无维护按钮，学生学情页要求教师登录。
2. API 验证：未登录与普通非教师账号均不能写 questions，不能读取 student_records，也不能上传图片；直接访问 API 同样被 RLS 拒绝。
3. 教师登录：新增一题并上传图片；设补录完成 10、错误 2，公开错误率为 20%。
4. 为该题新增 S001，完成 2、错误 1；公开完成为 12、错误为 3、错误率为 25%，公开接口不包含 S001。
5. 在另一浏览器确认 10 秒左右刷新；同一条记录从两个窗口修改应提示版本冲突。
6. 错误次数超过完成次数，浏览器和数据库均拒绝；删除题目后个人记录消失。

自动化验证：运行 `npm test`。本地自动化验证不能代替正式项目上的 RLS 与存储测试。
